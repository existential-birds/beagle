# Review Verification Protocol — Elixir / OTP / Phoenix delta

**Load `beagle-core:review-verification-protocol` first.** It carries the hard gates, the Pre-Report Verification Checklist, Severity Calibration, the imported `beagle-core:verification-budget` vocabulary (risk tiers, loop budgets, the one-echo rule, the prove-a-negative ban), and the language-neutral Verification by Issue Type sections.

This file adds **only** what is specific to Elixir, OTP, Phoenix, and LiveView. Everything else is in the core; nothing here overrides it.

## Verification by Issue Type — Elixir specifics

### "Unused Variable/Function"

Run the core's four-pattern reference search. Elixir reference patterns that plain grep misses:

- Dynamic invocation via `apply/3`, MFA tuples, or module names built at runtime
- Functions referenced from config (`config :app, :handler, MyMod`) or from a supervision child spec
- Callbacks required by a `@behaviour` or generated by a macro (`use GenServer`, `use Phoenix.LiveView`)
- Functions called only from `~H` templates or `.heex` files

If dynamic invocation is plausible and you cannot confirm it, report the finding as a **question**, not a defect.

### "Missing Validation/Error Handling"

Before flagging, check whether responsibility already sits at the plug pipeline, the context module, a changeset, or the supervision tree. A process that is allowed to crash under a supervisor is often the intended design, not missing error handling.

### "Type Assertion/Unsafe Cast"

Pattern matching and guards are narrowing, not casting:

```elixir
# Pattern matching, NOT type casting
%UserData{} = data = load_user()

# Guard clauses narrow the type safely
def process(%User{name: name} = user) do
  name  # Elixir knows this is a User struct
end
```

### "Potential Leak / Race Condition"

- Check whether a supervisor restarts or cleans up the process
- Check for `Process.monitor`, `terminate/2`, or `on_mount` teardown before claiming a leak
- Confirm shared state is genuinely shared — separate processes have separate heaps

## Valid Patterns (Do NOT Flag)

### Elixir

| Pattern | Why It's Valid |
|---------|----------------|
| `case` with multiple clauses | Standard pattern matching, not excessive branching |
| `with` chains | Idiomatic for sequential operations that may fail |
| Pipe operator (`\|>`) chains | Elixir's core composition pattern |
| `@spec` without Dialyzer enforcement | Documentation value even without static analysis |
| `defp` private functions | Proper encapsulation, not hidden complexity |

### Phoenix / LiveView

| Pattern | Why It's Valid |
|---------|----------------|
| `assign/2` in `mount/3` | Standard LiveView state initialization |
| `handle_event/3` returning `{:noreply, socket}` | Correct for UI-triggered state updates |
| `~H` sigil for inline templates | Valid for small components |
| `on_mount` hooks | Correct lifecycle pattern for auth/setup |
| PubSub broadcasts in `handle_info` | Standard real-time communication pattern |

### Testing

| Pattern | Why It's Valid |
|---------|----------------|
| `assert` without a message | ExUnit provides clear diff output |
| `setup` block for test context | Standard ExUnit fixture pattern |
| `describe` blocks for grouping | Idiomatic test organization |
| `conn` pipeline in controller tests | Phoenix test helper convention |

## Context-Sensitive Rules

Each list below is an enumerated check, evaluated once. If an item is undecidable, drop the finding or ship it as a question — do not open another verification pass.

### Pattern Matching

Flag a missing pattern match **ONLY IF ALL** of these hold:
- [ ] The function receives structured data that should be destructured
- [ ] Not a pass-through function that forwards data unchanged
- [ ] The pattern match would prevent an actual runtime error
- [ ] Not a GenServer callback with a standard signature

### Process Architecture

Flag missing supervision **ONLY IF**:
- [ ] The process is long-lived (not a `Task`)
- [ ] A crash would affect system stability
- [ ] No supervisor already manages this process
- [ ] Not a test-only process

### Error Handling

Flag missing error handling **ONLY IF**:
- [ ] No `with` clause handles the error case
- [ ] No supervision tree restarts the process
- [ ] The error would cascade beyond the current process
- [ ] The user needs specific feedback for this error type
