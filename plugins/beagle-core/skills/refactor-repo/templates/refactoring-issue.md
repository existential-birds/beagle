# Refactoring Issue Review Template

The helper renders the corresponding fields from the accepted proposal ledger.
Use this checklist with `read_file` before posting; do not submit placeholders.

## Problem
A specific current structural obstacle, not "this file is too long."

## Why this change is worthwhile
Observed repeated maintenance work, propagation cost, or a known upcoming change.

## Evidence
Commit-pinned path/line links, enclosing symbols, relevant callers, and counterevidence checked.

## Fowler diagnosis
Named smell plus proposed catalog transformations and source chapters.

## Proposed small-step sequence
Tests first where protection is missing; incremental moves leaving behavior intact.

## Behavior and compatibility invariants
Outputs, error behavior, units, ordering, identity, persistence, concurrency, and public contracts as applicable.

## Validation plan
Existing test locations, newly required cases, and only repository-verified commands.

## Acceptance criteria
Observable structural outcomes and behavior checks that demonstrate the proposal is finished.

## Non-goals
Feature changes, unrelated cleanup, generated-output edits, and broad rewrites excluded explicitly.

## Risks and alternatives
Migration prerequisites, why the present boundary may be intentional, and the no-change option.

## Priority, effort, and related work
Justified ordinal ranking, existing labels, requested assignee, and semantically checked issues/PRs.

## Validation performed during survey
Distinguish actual executed checks from planned checks; this is a proposal, not an implementation receipt.
